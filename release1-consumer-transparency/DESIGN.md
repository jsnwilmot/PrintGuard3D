# Phase B design decision — 2026-10-30 UTC

Issue #27; approved main/Phase A merge `d6a28ccb79f0a57a3cec4ea7cd7776feae9fb634`; branch `release1/privacy-consumer-transparency`. PR #28 confirmed merged. Latest Architect start instruction: issue comment 6524544601. This design precedes implementation.

Add one shared, bundled **Data handling information** component, publicly readable in Help and an existing accessible modal opened from Settings/footer. It contains factual descriptions and explicit deployment uncertainty, not an adopted final privacy policy or amended terms. Information revision **1.0 (2026-10-30)** identifies the copy only. No consent checkbox, preference, acknowledgment renewal, new retention timer, analytics, network endpoint, database/schema/profile/backup-format change or data migration. Disclaimer v1.0 and its acknowledgment are unchanged. The separate DRAFT-PRIVACY-NOTICE.md is owner-review-only and is not bundled as a final policy.

Reuse the existing Modal, public Help route and footer. Public information receives no workshop data and requires no new database reads. All existing protected record queries remain behind the current device acknowledgment gate. A brief shared backup summary appears beside backup actions; report exports are not recovery backups. No new delete/restore implementation is needed: describe existing behavior, including observation retention during printer deletion/replacement, copies outside browser storage, and old-reader limitations accurately.

Preserve Phase A ManufacturerNotice, source hazard policy, context gate, exportSafety, recommendationPolicy and immutable profiles/history. Audit existing warnings through tests rather than duplicate export machinery. Source review + isolated synthetic production-build browser requests establish only application design/loopback observations. They cannot prove live host/CDN logging, cookies, DNS, processor terms, retention, geography, actual mailbox control or public access behavior. Owner/host facts and market/language decisions remain explicit open gates.

Multi-AI workflow is an unexecuted owner review framework, with exact prompt/date/model/source/evidence/decision fields and unresolved Q identifiers. No invented AI answers or signatures, sensitive chat transcripts, counsel signoff, legal compliance or release approval. No jurisdiction exclusions or French translation are implemented. Final policy adoption and any material terms/consent change require separate owner authorization.
