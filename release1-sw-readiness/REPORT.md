## Findings and confidence

1. **HIGH: readiness and page control are different milestones.** The event ledger repeatedly observes a resolved `navigator.serviceWorker.ready` while `controller` is still null, followed by controllerchange. A registration with an active old worker is also ready while a compatible newer worker waits. The held-tab scenario then activates the exact compatible candidate through the target/control protocol, keeps old HTML in memory and preserves every store. None of these expected intermediate states alone establishes an indefinite hang.
2. **HIGH for controlled faults: install failure can leave readiness pending.** Injecting a503 or mismatching bytes for a precached SVG produces an uncontrolled online workshop with no completed offline cache. All six engine/fault cases preserve records, validate a full backup, refuse a real write after an explicit native future-generation fixture, fail cold offline startup, and recover the same records online. These are reproducible negative controls, not reproductions of the old unexplained failure.
3. **HIGH for controlled App failure: registration depends on successful dynamic import.** `src/main.tsx` registers only inside the resolved App import. The injected App503 exposes the existing asset-unavailable fatal message; no worker registration is observed. Chromium/WebKit complete the scenario oracle. Firefox reaches the fatal heading but a diagnostic state query throws an opaque `{}`; that case remains FAIL, not converted into a successful expected-negative case.
4. **HIGH: a user-facing offline-preparation warning gap exists in the injected-install cases.** The online dashboard remains usable, but none of the six503/hash cases exposes an explicit SW/offline-install failure warning. The empty register catch also cannot report later install/activation failure. This is a proposed corrective scope; it is not identified as the cause of N09.
5. **HIGH for the local encoding fixture: recorded text bytes are not necessarily delivered bytes.** All four Chromium charset × routing controls have identical native page/worker/server SHA256 values. Without explicit charset, the trace stores a52-byte text representation of the44-byte CSS; explicit UTF-8 aligns it. Thus the old trace's CSS representation discrepancy cannot by itself establish a real precache hash mismatch. This does not prove the old install succeeded.
6. **NOT VERIFIED: universal first-page/installed-PWA reliability.** Thirty unchanged N09 cases and all120 diagnostic clean-start cells pass locally, but those finite samples do not explain the retained failures, rule out rare lifecycle/clock/resource races, or verify installed PWA/OS/Safari/iOS behavior.
