## F1 design

`release-contract.json` explicitly declares a release version, writer protocol/generation/capabilities, native layout, immutable approved baseline, compatibility classification, reasoning and evidence. Compatible declarations retain the baseline generation; same-format writer bumps must increase it. Unknown capabilities/layouts or format transitions STOP. A baseline before this manifest is accepted only at the exact approved #38 merge; later baselines come from their immutable Git object.

Ordinary builds and fixture overrides are NON-DEPLOYABLE and refuse canonical-host workshop bootstrap. Release mode has no fallback: it requires a clean source tree, an exact SHA/content-build-bound compatibility decision and an Ed25519 reviewer signature from the checked-in, independently reviewed public-key register. No private key is stored. The initial register is deliberately empty: this draft cannot manufacture independent review or produce a public release. Reviewer enrollment/key custody/rotation requires explicit independent disposition before a release. Synthetic tests use disposable keys only. Signatures attest a human compatibility decision; neither code nor hashing can infer semantic compatibility or legal/release approval. Arbitrary modifications to validator/trust/source or bypassing the documented release command remain outside this gate's trust boundary.

## F2 design

The review authority is bound to an exact waiting ServiceWorker object plus its message-channel build/contract identity, executing build identity and persisted control snapshot. A changing candidate/control, offline event, error, missing/unknown identity, unmount or acknowledgment change invalidates download/review permission. Backups completing after invalidation remain downloadable but do not authorize the new candidate.

Interval/focus reads are serialized: a five-second worker timeout must not be perpetually superseded by a three-second poll. The first current error invalidates authority. Lifecycle interruption cancels old callbacks and revokes authority immediately; unmount stops callbacks. Native G06 deliberately drops identity replies, performs no activation click, and requires background polling alone to clear confirmation within15seconds.

Every activation/adoption refreshes and compares the reviewed snapshot immediately before use. Adoption retains the existing native compare-and-advance transaction. Worker activation targets the exact worker and carries its identity and expected persisted control; the worker independently checks both before calling skipWaiting. It cannot activate a replacement worker using a prior build's message. No activation on unknown, unsupported or offline state. The existing supported workshop continues offline; update confirmation can be resumed after reconnecting and fresh review.

Browser worker state and IndexedDB cannot form one cross-system atomic transaction. Target-specific messages, a worker-side control read, native adoption comparison and the existing ordinary-write fence bound the remaining race. A control can advance immediately after a successful worker read; this cannot grant stale data writes. Other tabs may activate their own reviewed update. Browser-reported offline state invalidates review; navigator.onLine is a hint, not proof that the origin/network is reachable. The current offline cache and workshop remain usable. No silent cache deletion, record rewrite or forced timeout reload is introduced. Downloading still does not prove independently tested restoration.

The former unbound activation message is deliberately refused without a reply port, exact target and expected control. The accepted #38 binary was not deployed publicly; its old direct activation message cannot authorize this new worker. Existing N11's candidate-delivery setup is adapted to the new actual handshake; its consent, preservation and adoption assertions remain identical. N02 continues through the actual UI. First-public participating release must include this protocol; no claim of automatic retrofit to arbitrary old workers is made.

## Reproduction and signoff format

Normal `npm run build` remains localhost-testable, emits `dist/build-contract.json` with deployable:false, and refuses canonical workshop bootstrap before App/DB/worker import. `PRINTGUARD_FIXTURE=1` plus a generation override is only for explicit local nondeployable fixtures. Release mode rejects fixture/test overrides.

After independent approval and a separately reviewed public-key enrollment, a release operator checks out the exact clean reviewed SHA. `npm run release:describe` prints the artifact payload and PENDING review template; it is not an approval. The reviewer independently verifies that SHA/build identity, baseline/compatibility reasoning, evidence and source diff, supplies reviewerId/reviewedAt/reference/decision:approved, and signs the UTF-8 bytes returned by `canonical({schemaVersion:1,artifact,review})` using an offline Ed25519 private key. Only the base64 signature and public reviewer identity belong in the detached review JSON. The private key must never enter this repo, CI, browser or report. The independently approved public-key register resides in release-contract.json. The final exact artifact gets its own signature; a changed SHA, build, policy, reviewer or date invalidates the old signature.

An authorized operator later supplies that detached file through build-time PRINTGUARD_RELEASE_REVIEW and invokes `npm run build:release`. Missing approval, dirty source, unknown signer, altered payload/signature, old generation for writer-bump or unsupported formats fail before Vite writes a new release output. A previous dist may still exist after a failed build and must never be treated as its output. This command has no upload/deploy/Cloudflare behavior. An approved cryptographic compatibility attestation is not merge, hosting, legal or Release 1 authorization. CI's current positive signatures are generated disposable synthetic keys; the real register remains empty, so producing a public artifact from this draft is intentionally blocked.

Commands for regression and native reproduction are the preserved TEST-PLAN commands, plus `node release1-release-governance/run.mjs <prepared-clean-origin-directory>`. Preparation now adds a third generation-1 fixture changing only the document title. It is declared compatible, has a different executable identity and shares the same writer/data semantics. The generation-2 fixture exercises monotonic adoption and stale refusal. All fixture outputs remain nondeployable. The additive cases await serviceWorker.ready, explicitly navigate into that active cached application, and verify every store plus its controller before arranging an update. This is controlled-session preparation; it does not claim a guaranteed cold-first-page clients.claim deadline. The unchanged original N02/N11 workflows remain separate. The native ledger records exact runner/harness hashes as well as the frozen application commit.
