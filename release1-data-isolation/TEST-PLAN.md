After independent design review and separate implementation authorization, extend isolated localhost testing using new short disposable browser profile directories and unique loopback origins per version/combination. Never use the private site, ordinary browser data, real backups or unapproved external preview. Keep the historical archives and [original audit](../release1-operational-preflight/README.md) unchanged. Add a separately identified isolated-target runner rather than replace recorded failures with a new interpretation.

Use actual unchanged historical sources `616e26ee5c0834a3d0900294981bcf8963d2c053` and `d03eb59cb887cfad335241b9f56d260b5a75abdc`, original current-source control aa6ae5892fde8e0d621bbb34b765c41739e7a2ba, and an exact newly authorized implementation SHA. Record build/probe/asset/lock digests, library versions versus schema verno/native versions, UTC, synthetic test clock, origin/profile mapping, native stores, input/backup hashes, expected/actual and per-case status. Store full synthetic snapshots/controller/server events and safe screenshots. A harness timeout is NOT proof of safe refusal. Unexpected setup errors make dependent checks NOT EXECUTED until fixed and rerun.

Run each executable case in Chromium, Firefox and WebKit. Build inputs set a reviewed fixed destination constant; tests must not make old source choose another name or replace its writer with a mock. Inspect both `S` and `D` using test-only native read transactions. Assert that old actions actually occurred on `S` as a positive control; a failed click or wrong locator is not a protected-destination PASS.

Fixture includes Creator 5 and Pro separately, archived printer, resin/custom rules, original immutable profile versions, daily 5/10 boundary choices (four inspection-only opt-ins), baseline readings, photos/long notes, CAD/USD/unknown historical costs, completions with/without legitimate legacy metadata, source flags and prospective observations. Include deliberately incomplete post-baseline stale-written logs as **negative** inputs, never quietly relabel them valid legacy. Test empty/one/large workshops, capacity boundaries and dates through 2035, 2400 and beyond.

A live web application cannot create a user's separate browser profile by itself. Independent restore rehearsal must be carried out by authorized local test tooling or the user/IT in a genuinely disposable profile/origin, with the exact supported build/file. A user's checkbox that they rehearsed is not technical proof; capture actual readback evidence for acceptance. No temporary per-build production database fleet is required to simulate an independent profile.
